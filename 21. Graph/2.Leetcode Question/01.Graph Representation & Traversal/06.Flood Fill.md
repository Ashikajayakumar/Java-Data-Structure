## 📌 Problem

You are given an `m x n` image.

Each number represents the **color of a pixel**.

For example:

```text
image =

[
 [1, 1, 1],
 [1, 1, 0],
 [1, 0, 1]
]
```

You are also given:

```text
sr = 1
sc = 1
color = 2
```

This means:

> Start from the pixel at row `1`, column `1` and change its color to `2`.

Then change all pixels that:

1. Have the **same original color**.
2. Are directly connected to the starting pixel.
3. Are connected horizontally or vertically.



# 🖼️ Example

Input:

```text
image = [
    [1, 1, 1],
    [1, 1, 0],
    [1, 0, 1]
]

sr = 1
sc = 1

color = 2
```

Let's number the positions:

```text
        col
        0   1   2

row 0   1   1   1
row 1   1   1   0
row 2   1   0   1
```

Starting position:

```text
(sr, sc) = (1, 1)
```

So:

```text
        0   1   2
      ┌───┬───┬───┐
  0   │ 1 │ 1 │ 1 │
      ├───┼───┼───┤
  1   │ 1 │ 🔴│ 0 │
      ├───┼───┼───┤
  2   │ 1 │ 0 │ 1 │
      └───┴───┴───┘
            ↑
         (1,1)
```

The starting color is:

```text
originalColor = 1
```

We need to change all connected `1`s to `2`.

---

# 🔑 Important Concept: What Does "Connected" Mean?

Only **4 directions** are allowed.

```text
        (r-1,c)
           ↑
           |
(r,c-1) ← (r,c) → (r,c+1)
           |
           ↓
        (r+1,c)
```

We **DO NOT** consider diagonals.

For example:

```text
1  0
0  1
```

The two `1`s are **NOT connected**.

Because they only touch diagonally.

# 💻 Java Solution — DFS

```java
class Solution {

    public int[][] floodFill(  int[][] image,int sr,int sc,int color) {
        int originalColor = image[sr][sc];
        if (originalColor == color) {
            return image;
        }
        dfs(image, sr, sc, originalColor, color);
        return image;
    }

    private void dfs(int[][] image,int row,int col,int originalColor,int newColor) {
        image[row][col] = newColor;

        // Up
        if (row > 0 && image[row - 1][col] == originalColor) {
            dfs(image,row - 1,col,originalColor,newColor);
        }

        // Down
        if (row + 1 < image.length && image[row + 1][col] == originalColor) {
            dfs(image,row + 1,col,originalColor,newColor);
        }

        // Left
        if (col > 0 && mage[row][col - 1] == originalColor) {
            dfs(image,row,col - 1,originalColor,newColor);
        }

        // Right
        if (col + 1 < image[0].length && image[row][col + 1] == originalColor) {
            dfs(image, row, col + 1, originalColor, newColor);
        }
    }
}
```

# ⭐ Easier Version Using Directions Array

The above code is beginner-friendly because every direction is written separately.

Once you understand it, we can make it shorter using:

```java
int[][] directions = {
    {-1, 0}, // up
    {1, 0},  // down
    {0, -1}, // left
    {0, 1}   // right
};
```

Then:

```java
class Solution {
    public int[][] floodFill( int[][] image, int sr, int sc, int color) {
        int originalColor = image[sr][sc];
        if (originalColor == color) {
            return image;
        }

        dfs(image, sr, sc, originalColor, color);
        return image;
    }

    private void dfs( int[][] image,int row,int col,int originalColor,int color) {
        image[row][col] = color;
        int[][] directions = {
            {-1, 0},  // up
            {1, 0},   // down
            {0, -1},  // left
            {0, 1}    // right
        };

        for (int[] direction : directions) {

            int newRow = row + direction[0];
            int newCol = col + direction[1];

            if (newRow >= 0 && newRow < image.length && newCol >= 0 && newCol < image[0].length && image[newRow][newCol] == originalColor) {

                dfs(image,newRow,newCol,originalColor,color);
            }
        }
    }
}
```

# 🧠 Important: Why Does Bottom-Right Stay `1`?

This is the most important concept in this problem.

Look at:

```text
2 2 2
2 2 0
2 0 1
      ↑
```

The last `1` is:

```text
(2,2)
```

Its neighbors:

```text
       (1,2) = 0
          ↑
          |
(2,1)=0 ← (2,2)=1
```

There is no path through another `1`.

Therefore it is **not part of the flood-fill region**.

### ❌ Diagonal does NOT count

```text
2 2
2 1
  ↘
```

The `1` is diagonal.

It cannot be reached using:

```text
UP
DOWN
LEFT
RIGHT
```

# 🧩 How DFS Thinks

At every pixel:

```text
             Current
                |
       ┌────────┼────────┐
       ↓        ↓        ↓
      UP       DOWN     LEFT
                         +
                        RIGHT
```

Actually, exactly four directions:

```text
          UP
           ↑
           |
LEFT ← CURRENT → RIGHT
           |
           ↓
         DOWN
```

For every direction:

```text
Is it inside the image?
        ↓
Is its color equal to original color?
        ↓
YES → DFS
NO  → Ignore
```

---

# 🔥 Why Do We Change the Color Immediately?

This line is important:

```java
image[row][col] = color;
```

Suppose we have:

```text
1 1
1 1
```

We start at `(0,0)`.

Change immediately:

```text
2 1
1 1
```

Now if DFS comes back to `(0,0)`, it sees:

```text
image[0][0] = 2
```

But original color is:

```text
1
```

So:

```text
2 != 1
```

It won't visit `(0,0)` again.

Therefore, **changing the pixel acts like marking it visited**.

# 🎯 Important Code Sections

### 1️⃣ Store original color

```java
int originalColor = image[sr][sc];
```

We must remember the **original** color before changing anything.

---

### 2️⃣ Handle same-color case

```java
if (originalColor == color) {
    return image;
}
```

Nothing needs to change.

---

### 3️⃣ Start DFS

```java
dfs(image, sr, sc, originalColor, color);
```

---

### 4️⃣ Change current pixel

```java
image[row][col] = color;
```

This also effectively marks the pixel as visited.

---

### 5️⃣ Calculate neighboring position

```java
int newRow = row + direction[0];
int newCol = col + direction[1];
```

For example:

```text
Current = (1,1)
```

UP:

```text
(-1,0)

(1 + -1, 1 + 0)
= (0,1)
```

RIGHT:

```text
(0,1)

(1 + 0, 1 + 1)
= (1,2)
```

---

### 6️⃣ Check boundaries

```java
newRow >= 0 &&
newRow < image.length &&
newCol >= 0 &&
newCol < image[0].length
```

This prevents accessing something like:

```text
image[-1][0]
```

which would cause an error.

---

### 7️⃣ Check original color

```java
image[newRow][newCol] == originalColor
```

Only pixels having the **starting pixel's original color** should be changed.

# ⏱️ Complexity

Let:

```text
m = number of rows
n = number of columns
```

### Time Complexity

```text
O(m × n)
```

In the worst case, we may visit every pixel once.

### Space Complexity

```text
O(m × n)
```

In the worst case, the DFS recursion stack can contain many pixels.

# 🧠 Interview Explanation

If the interviewer asks:

**"Explain your approach."**

You can say:

> I use DFS starting from the given source pixel. First, I store the original color of the source pixel. Then I change the current pixel to the new color and recursively visit its four adjacent pixels — up, down, left, and right. I only visit a pixel if it is inside the image and has the same original color. I also handle the case where the original color is already equal to the new color. Finally, I return the modified image.

# ⭐ Pattern to Remember

This problem teaches an important **Grid DFS** pattern:

```text
                 START
                   ↓
            Change current
                   ↓
        ┌──────────┼──────────┐
        ↓          ↓          ↓
       UP        DOWN        LEFT
                              ↓
                            RIGHT
        └──────────┬──────────┘
                   ↓
          Check boundary
                   ↓
       Check original color
                   ↓
              DFS again
```

### 🔥 One-line memory trick

```text
GRID + STARTING CELL + SAME COLOR + 4 DIRECTIONS = FLOOD FILL
```

And the key DFS condition is:

```java
inside grid
      &&
same original color
      ↓
     DFS
```

This is the same **DFS/connected-component thinking** you used in **LeetCode 547 — Number of Provinces**, but here the graph is represented as a **2D grid** instead of a connection matrix.
