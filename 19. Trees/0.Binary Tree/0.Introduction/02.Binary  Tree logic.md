How to identify the correct logic for Binary Tree questions in Java
For your Infosys Specialist Programmer / Digital Specialist Engineer preparation, the most important skill is identifying which approach a question requires before writing code.

A binary tree question may look unfamiliar, but you can often classify it by its keywords, expected output, and what information you need to calculate. 
1. The 4-method identification trick 
  
Method 1: Queue (BFS)     
Level by level     
Look for these clues:       
- Level order           
- Each level separately     
- Left-to-right at each depth  
- Right-side view or minimum depth    
Ask yourself: Do I need to process all nodes at one level before moving to the next? 

Template: Queue<TreeNode> + while + q.size(). 

Method 2: Recursion (DFS) 
Calculate subtree results
Look for these clues:
- Maximum or minimum depth 
- Height, diameter or balance
- Count nodes
- Calculate a property from left and right children
Ask yourself: Can I solve the problem for each child and combine their answers?

Template: Base case → left result → right result → combine.


Method 3: Track a path or state
Carry information
Look for these clues:
- Root-to-leaf path
- Target sum
- Find a path or all paths
- Track depth, ancestors or a maximum path value
Ask yourself: Must I remember information accumulated while travelling from the root to a node?

Template: Pass parameters into recursion, or maintain a path list / shared answer as needed.


Method 4: Subtree comparison
Compare structures
Look for these clues:
- Same tree
- Symmetric tree
- Is one tree a subtree of another?
- Compare left and right branches
Ask yourself: Do I need to compare two nodes, two branches, or two tree structures?

Template: Check null cases → compare values → recursively compare children.
