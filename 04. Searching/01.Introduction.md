## 📌 What is Searching?

Searching is the process of **finding a particular element (target/key)** in a collection of data such as an array, list, or other data structure.

👉 The goal of searching is to determine:

* Whether the element exists
* Where the element is located
* Sometimes how many times it occurs

📌 Example:

```text
Array = [10, 20, 30, 40, 50]
Target = 30

Output → Element found at index 2
```

Searching is one of the **most fundamental concepts in DSA**.

We use searching when we need to quickly find data from a collection.

# 📚 Types of Searching

There are two fundamental searching techniques:

### 1️⃣ Linear Search

* Works on sorted and unsorted data
* Checks elements one by one
* Simple to implement

### 2️⃣ Binary Search

* Requires sorted data
* Eliminates half of the search space in every step
* Much faster than Linear Search for large datasets

---

# 1️⃣ Linear Search

## 📌 What is Linear Search?

Linear Search checks every element **one by one** from the beginning until the target element is found.

It is also called **Sequential Search**.

### Example

```text
Array = [10, 25, 30, 45, 50]
Target = 45

Step 1 → 10 ❌
Step 2 → 25 ❌
Step 3 → 30 ❌
Step 4 → 45 ✅
```

Therefore:

```text
Element found at index 3
```

---

## 🔄 Linear Search Algorithm

1. Start from the first element.
2. Compare the current element with the target.
3. If they are equal, return the index.
4. Otherwise, move to the next element.
5. Repeat until the element is found.
6. If the array ends, return `-1`.

---

## 💻 Java Implementation

```java
public class LinearSearch {

    public static int search(int[] arr, int key) {

        for (int i = 0; i < arr.length; i++) {

            if (arr[i] == key) {
                return i;
            }
        }

        return -1;
    }

    public static void main(String[] args) {

        int[] arr = {10, 25, 30, 45, 50};
        int key = 45;

        int result = search(arr, key);

        if (result != -1) {
            System.out.println("Element found at index " + result);
        } else {
            System.out.println("Element not found");
        }
    }
}
```

### 📤 Output

```text
Element found at index 3
```

---

## ⏱️ Linear Search Complexity

| Case         | Time Complexity |
| ------------ | --------------- |
| Best Case    | **O(1)**        |
| Average Case | **O(n)**        |
| Worst Case   | **O(n)**        |
| Space        | **O(1)**        |

### 📌 Best Case

Target is present at the first position.

```text
[50, 10, 20, 30]
 ↑
Target
```

Only one comparison is required.

👉 **O(1)**

### 📌 Worst Case

Target is at the last position or does not exist.

```text
[10, 20, 30, 40, 50]
                     ↑
                  Target
```

All elements may need to be checked.

👉 **O(n)**

# 2️⃣ Binary Search

## 📌 What is Binary Search?

Binary Search is an efficient searching algorithm that repeatedly **divides the search space into two halves**.

⚠️ **Important:** Binary Search requires the array to be **sorted**.

### Example

```text
Array = [10, 20, 30, 40, 50, 60, 70]
Target = 60
```

Instead of checking every element:

```text
Step 1:
        [10 20 30 40 50 60 70]
                    ↑
                   mid

Target > mid
Search right half
```

```text
Step 2:
        [50 60 70]
           ↑
          mid

Target > mid
Search right half
```

```text
Step 3:
        [60 70]
         ↑
       Target
```

Element found.

---

# 🔄 Binary Search Algorithm

1. Set `low = 0`.
2. Set `high = n - 1`.
3. Calculate the middle index.
4. Compare `arr[mid]` with the target.
5. If equal → element found.
6. If target is greater → search the right half.
7. If target is smaller → search the left half.
8. Repeat until `low > high`.
9. Return `-1` if the element is not found.

---

## 💻 Java Implementation — Iterative

```java
public class BinarySearch {

    public static int search(int[] arr, int key) {

        int low = 0;
        int high = arr.length - 1;

        while (low <= high) {

            int mid = low + (high - low) / 2;

            if (arr[mid] == key) {
                return mid;
            }
            else if (arr[mid] < key) {
                low = mid + 1;
            }
            else {
                high = mid - 1;
            }
        }

        return -1;
    }

    public static void main(String[] args) {

        int[] arr = {10, 20, 30, 40, 50, 60, 70};
        int key = 60;

        int result = search(arr, key);

        if (result != -1) {
            System.out.println("Element found at index " + result);
        } else {
            System.out.println("Element not found");
        }
    }
}
```

### 📤 Output

```text
Element found at index 5
```

---

# ⚠️ Important Binary Search Condition

The array should be **sorted**.

### ✅ Correct

```text
[10, 20, 30, 40, 50, 60]
```

### ❌ Not suitable for normal Binary Search

```text
[30, 10, 50, 20, 40, 60]
```

If the array is unsorted, use **Linear Search** or sort the data first.

---

# 🧠 Why is Binary Search Faster?

Consider an array containing:

```text
1,000,000 elements
```

### Linear Search

May check up to:

```text
1,000,000 elements
```

### Binary Search

The search space is approximately halved each time:

```text
1,000,000
   ↓
500,000
   ↓
250,000
   ↓
125,000
   ↓
...
   ↓
1
```

So Binary Search takes approximately:

```text
O(log n)
```

---

# ⏱️ Binary Search Complexity

| Case              | Time Complexity |
| ----------------- | --------------- |
| Best Case         | **O(1)**        |
| Average Case      | **O(log n)**    |
| Worst Case        | **O(log n)**    |
| Space – Iterative | **O(1)**        |

---

# ⚔️ Linear Search vs Binary Search

| Feature                         | Linear Search    | Binary Search    |
| ------------------------------- | ---------------- | ---------------- |
| Data must be sorted?            | ❌ No             | ✅ Yes            |
| Searching method                | Sequential       | Divide & Conquer |
| Best Case                       | O(1)             | O(1)             |
| Average Case                    | O(n)             | O(log n)         |
| Worst Case                      | O(n)             | O(log n)         |
| Space                           | O(1)             | O(1)             |
| Easy to implement?              | ✅ Yes            | ⭐ Moderate       |
| Suitable for large sorted data? | ❌ Less efficient | ✅ Very efficient |

# 🎯 Interview Takeaways

Before solving a searching problem, ask:

### 1️⃣ Is the data sorted?

```text
Yes → Think about Binary Search
No  → Think about Linear Search / other techniques
```

### 2️⃣ What is the required time complexity?

If the interviewer expects:

```text
O(n)
```

Linear Search may be enough.

If the interviewer expects:

```text
O(log n)
```

Think **Binary Search**.

### 3️⃣ Can the search space be divided?

If yes, Binary Search may be applicable.
