# LeetCode 1029 – Two City Scheduling

Greedy Algorithm | Sorting | Medium

## 1. Problem Statement

A company is planning to send `2n` people to attend an event in two different cities:

- City A
- City B

Each person has two possible travel costs:

- `costs[i][0]` – Cost of sending person `i` to City A.
- `costs[i][1]` – Cost of sending person `i` to City B.

Your task is to send exactly `n` people to City A and exactly `n` people to City B, while minimizing the total travel cost.

Return the minimum possible total cost.

## 2. Example

Input:

```
costs = [[10,20],
         [30,200],
         [400,50],
         [30,20]]
```

Output:

```
110
```

Explanation:

There are 4 people, so exactly 2 people must go to each city.

| Person   | City A Cost | City B Cost | Selected City |
| -------- | ----------- | ----------- | ------------- |
| Person 0 | 10          | 20          | A             |
| Person 1 | 30          | 200         | A             |
| Person 2 | 400         | 50          | B             |
| Person 3 | 30          | 20          | B             |

Total cost:

`` 10+30+50+20=\boxed{110} ``

## 3. Important Points

1. There are `2n` people.
2. Exactly `n` people must go to City A.
3. Exactly `n` people must go to City B.
4. Each person can go to only one city.
5. We need to minimize the total cost, not simply choose the cheapest city independently for every person.

Important observation: We should compare the cost difference between sending each person to City A and City B.

## 4. Main Concept – Greedy + Sorting

The key idea is to find which city gives the greatest savings for each person.

Calculate:

`` difference = costA-costB ``

There are three possibilities:

| Difference | Meaning            | Preferred City |
| ---------- | ------------------ | -------------- |
| Negative   | City A is cheaper  | City A         |
| Positive   | City B is cheaper  | City B         |
| Zero       | Both cost the same | Either city    |

We sort people by this difference in ascending order.

- First `n` people → City A.
- Remaining `n` people → City B.

Why?

People with the most negative differences benefit most from going to City A. People with the largest positive differences benefit most from going to City B.

## 5. Main Logic – Step by Step

1. Sort the `costs` array based on `costA - costB`.
2. The first `n` people have the strongest preference for City A.
3. Add their City A costs to the total.
4. Add the City B costs of the remaining `n` people.
5. Return the total cost.

## 6. Java Solution



Greedy + Sorting

Optimal



```
import java.util.Arrays;

class Solution {
    public int twoCitySchedCost(int[][] costs) {

        Arrays.sort(costs, (a, b) ->
            (a[0] - a[1]) - (b[0] - b[1])
        );

        int n = costs.length / 2;
        int totalCost = 0;

        for (int i = 0; i < costs.length; i++) {

            if (i < n) {
                totalCost += costs[i][0];
            } else {
                totalCost += costs[i][1];
            }
        }

        return totalCost;
    }
}
```

## 7. Understand the Code

Part A – Sorting based on cost difference

```
Arrays.sort(costs, (a, b) ->
    (a[0] - a[1]) - (b[0] - b[1])
);
```

Here:

- `a[0]` = Person A's City A cost.
- `a[1]` = Person A's City B cost.
- `a[0] - a[1]` = Difference for person A.

The same calculation is performed for person B.

The sorting arranges people from the strongest City A preference to the strongest City B preference.

For production-quality Java, avoid subtraction-based comparators because subtraction can overflow. A safer version is:

```
Arrays.sort(costs, (a, b) ->
    Integer.compare(a[0] - a[1], b[0] - b[1])
);
```

Part B – Find the number of people per city

```
int n = costs.length / 2;
```

If there are 4 people:

\\[ n=4/2=2 \\]

So, 2 people must go to each city.

Part C – Initialize total cost

```
int totalCost = 0;
```

This variable stores the total travel cost.

Part D – Select the city

```
for (int i = 0; i < costs.length; i++) {

    if (i < n) {
        totalCost += costs[i][0];
    } else {
        totalCost += costs[i][1];
    }
}
```

- If `i < n`, select City A.
- Otherwise, select City B.

Part E – Return the answer

```
return totalCost;
```

Returns the minimum total travel cost.

Sorted differences:

```
-170, -10, 10, 350
```

Sorted people:

| Position | Person | City A | City B | Difference |

| 2        | P3     | 30     | 20     | 10         |
| 3        | P2     | 400    | 50     | 350        |

Step 3 – Select two people for each city

Since `n = 2`:

- First two people → City A.
- Last two people → City B.

```
                 Sorted People
                       |
              -------------------
              |                 |
          City A             City B
          First 2            Last 2
              |                 |
           P1, P0             P3, P2
              |                 |
          30 + 10             20 + 50
              |                 |
             40                70
              |                 |
              ------ Total -----
                      |
                     110
```

| Iteration | i | Person | Condition     | Selected Cost | Total Cost |
| --------- | - | ------ | ------------- | ------------- | ---------- |
