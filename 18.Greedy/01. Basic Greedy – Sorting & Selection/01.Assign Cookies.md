
# LeetCode 455 – Assign Cookies

Greedy Algorithm | Sorting | Two Pointers | Easy

## 1. Problem Statement

There are `n` children and `m` cookies.

- Each child has a greed factor `g[i]`, which represents the minimum cookie size required to satisfy that child.
- Each cookie has a size `s[j]`.
- A child can receive at most one cookie.
- A child is satisfied if the cookie size is greater than or equal to their greed factor.

Your task is to assign cookies to children so that the maximum number of children are satisfied.

Return the maximum number of satisfied children.

## 2. Example

Example 1

```
Input:
g = [1, 2, 3]
s = [1, 1]

Output:
1
```

Explanation:

- Child 1 needs a cookie of size 1.
- Child 2 needs a cookie of size 2.
- Child 3 needs a cookie of size 3.

We have only two cookies, both of size 1.

Only the first child can be satisfied.

Example 2

```
Input:
g = [1, 2]
s = [1, 2, 3]

Output:
2
```

Explanation:

- Child 1 gets cookie size 1.
- Child 2 gets cookie size 2.

Both children are satisfied.

## 3. Important Points

1. Each child can receive only one cookie.
2. Each cookie can be assigned to only one child.
3. Cookie size must be greater than or equal to the child's greed factor.
4. We need to maximize the number of satisfied children.
5. We do not need to satisfy every child.

## 4. Main Concept – Greedy Algorithm

What is Greedy?

A greedy algorithm makes the best possible choice at the current step to achieve an overall optimal result.

For this problem:

- Give the smallest sufficient cookie to the least greedy child.
- Save larger cookies for children who need them.

Why?

If we give a large cookie to a child who needs only a small cookie, we may waste a cookie that could satisfy a more greedy child.

## 5. Main Logic – Sorting + Two Pointers

First, sort both arrays in ascending order.

```
Greed array:
g = [1, 2, 3]

Cookie array:
s = [1, 1]
```

Use two pointers:

- `i` → Tracks children.
- `j` → Tracks cookies.

Rules:

Condition 1: Cookie can satisfy the child

```
if (s[j] >= g[i])
```

- Child is satisfied.
- Move to the next child.
- Move to the next cookie.

Condition 2: Cookie is too small

```
else
```

- Current cookie cannot satisfy the child.
- Try the next larger cookie.
- Move only the cookie pointer.

## 6. Java Solution

```
import java.util.Arrays;

class Solution {
    public int findContentChildren(int[] g, int[] s) {

        Arrays.sort(g);
        Arrays.sort(s);

        int i = 0;
        int j = 0;

        while (i < g.length && j < s.length) {

            if (s[j] >= g[i]) {
                i++;
            }

            j++;
        }

        return i;
    }
}
```

## 7. Understand the Code

Part A – Sort both arrays

```
Arrays.sort(g);
Arrays.sort(s);
```

Sort the greed factors and cookie sizes in ascending order.

Example:

```
Before:
g = [3, 1, 2]
s = [2, 1, 3]

After:
g = [1, 2, 3]
s = [1, 2, 3]
```

Part B – Initialize pointers

```
int i = 0;
int j = 0;
```

- `i` starts from the first child.
- `j` starts from the first cookie.

Part C – Loop condition

```
while (i < g.length && j < s.length)
```

Continue while both children and cookies are available.

Part D – Check cookie size

```
if (s[j] >= g[i]) {
    i++;
}
```

If the cookie is big enough, satisfy the child and move to the next child.

Part E – Move cookie pointer

```
j++;
```

Whether the cookie satisfies the child or not, it has now been considered. Move to the next cookie.

Part F – Return answer

```
return i;
```

Since `i` counts the number of children satisfied, return it.

## 8. Complete Dry Run

Input:

```
g = [1, 2, 3]
s = [1, 1]
```

After sorting:

```
Children:  1   2   3
           ↑
           i

Cookies:   1   1
           ↑
           j
```

Iteration 1

```
g[i] = 1
s[j] = 1

1 >= 1 → true
```

Child 1 is satisfied.

```
i = 1
j = 1
```

Iteration 2

```
g[i] = 2
s[j] = 1

1 >= 2 → false
```

Cookie is too small. Try the next cookie.

```
i = 1
j = 2
```

Now `j == s.length`, so the loop stops.

Answer = `1`
