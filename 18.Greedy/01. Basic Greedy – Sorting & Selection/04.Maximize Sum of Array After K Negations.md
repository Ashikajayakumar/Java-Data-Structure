# **LeetCode 1005 — Maximize Sum of Array After K Negations**


## **1. Problem Statement**

You are given an integer array `nums` and an integer `k`.

In one operation, you can choose any index `i` and multiply `nums[i]` by `-1`.

You can perform this operation exactly `k` times.

Return the maximum possible sum of the array after performing exactly `k` operations.

### **Example 1**

```
Input:
nums = [4, 2, 3]
k = 1

Output:
5

Explanation:

Choose index 1:
2 → -2

Array = [4, -2, 3]

Sum = 4 + (-2) + 3 = 5
```

### **Example 2**

```
Input:
nums = [3, -1, 0, 2]
k = 3

Output:
6

Explanation:

Operation 1: -1 → 1
Operation 2: -1 → -1
Operation 3: -1 → 1

One optimal final array:
[3, 1, 0, 2]

Sum = 6
```

### **Example 3**

```
Input:
nums = [2, -3, -1, 5, -4]
k = 2

Output:
13

Explanation:

Flip -3 → 3
Flip -4 → 4

Array = [2, 3, -1, 5, 4]

Sum = 13
```

## **2. Important Points**

1. We can select any array element and change its sign.
2. We must perform exactly `k` operations.
3. Changing a negative number into a positive number increases the sum.
4. Changing a positive number into a negative number decreases the sum.
5. Changing zero to zero does not affect the sum.
6. If we have unused operations after all negative numbers become positive, we must consider the smallest absolute value.

## **3. Main Concept — Greedy Algorithm**

The main goal is to maximize the sum.

Think about these three situations:

**Case 1: Negative numbers exist**

```
-5 → 5
```

Flipping a negative number increases the sum by 10.

Therefore, we should flip negative numbers first, starting with the smallest numbers (most negative).

**Case 2: All numbers are positive and operations remain**

```
5 → -5
```

Flipping a positive number decreases the sum.

To minimize the damage, flip the smallest positive number.

**Case 3: Zero exists**

```
0 → -0 = 0
```

We can use remaining operations on zero without changing the sum.

This is why zero can make an odd number of remaining operations harmless.

## **4. Greedy Strategy — Step by Step**

We use sorting to arrange numbers in ascending order.

Example:

```
nums = [2, -3, -1, 5, -4]
k = 2
```

After sorting:

```
[-4, -3, -1, 2, 5]
```

Now:

1. Start from the smallest element.
2. If the element is negative and `k > 0`, flip it.
3. Decrease `k`.
4. Continue until there are no operations left or no negative numbers remain.
5. If `k` is still positive and odd, flip the element with the smallest absolute value.
6. Calculate the sum.

## **5. Complete Java Solution — Sorting Approach**

```
import java.util.Arrays;

class Solution {
    public int largestSumAfterKNegations(int[] nums, int k) {

        Arrays.sort(nums);

        for (int i = 0; i < nums.length; i++) {

            if (nums[i] < 0 && k > 0) {
                nums[i] = -nums[i];
                k--;
            }
        }

        if (k % 2 == 1) {

            Arrays.sort(nums);

            nums[0] = -nums[0];
        }

        int sum = 0;

        for (int i = 0; i < nums.length; i++) {
            sum += nums[i];
        }

        return sum;
    }
}
```

## **6. Understand the Code — Line by Line**

### **Part A — Sort the array**

```
Arrays.sort(nums);
```

Sorting arranges the elements in ascending order.

Example:

```
Before sorting:
[2, -3, -1, 5, -4]

After sorting:
[-4, -3, -1, 2, 5]
```

Why sort?

Because we want to process the most negative numbers first.

### **Part B — Flip negative numbers**

```
for (int i = 0; i < nums.length; i++) {

    if (nums[i] < 0 && k > 0) {
        nums[i] = -nums[i];
        k--;
    }
}
```

We check two conditions:

```
nums[i] < 0
```

The current element must be negative.

```
k > 0
```

We must still have operations remaining.

If both conditions are true:

```
nums[i] = -nums[i];
```

Changes the sign of the current number.

```
k--;
```

One operation has been used.

### **Part C — Handle remaining operations**

```
if (k % 2 == 1) {

    Arrays.sort(nums);

    nums[0] = -nums[0];
}
```

After flipping negative numbers, we may still have operations remaining.

There are two possibilities:

- `k` is even: No change to the final array is necessary.
- `k` is odd: We must flip one number an additional time.

Why only check odd `k`?

Because flipping the same element twice restores its original value.

```
5 → -5 → 5
```

Two operations cancel each other.

If `k` is odd, one flip remains after pairing the other operations.

We sort again so that the smallest element is at index `0`.

```
nums[0] = -nums[0];
```

We flip the smallest element to minimize the reduction in the sum.

### **Part D — Calculate the sum**

```
int sum = 0;

for (int i = 0; i < nums.length; i++) {
    sum += nums[i];
}
```

Add all the elements and return the result.

## **9. Special Case — Remaining K Is Odd**

Consider:

```
nums = [4, 2, 3];
k = 3;
```

After sorting:

```
[2, 3, 4]
```

There are no negative numbers to flip.

The first loop does not change the array.

Now:

```
k = 3

k % 2 = 1
```

Since `k` is odd, we must flip the smallest element.

```
nums[0] = -nums[0];
```

Updated array:

```
[-2, 3, 4]
```

Sum:

```
-2 + 3 + 4 = 5
```

Even though we have three operations, we only need one effective flip because the remaining two operations can cancel each other.
