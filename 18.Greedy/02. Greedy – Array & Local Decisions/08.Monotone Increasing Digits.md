# LeetCode 738 – Monotone Increasing Digits

Greedy Algorithm | String | Digit Manipulation | Medium

## 1. Problem Statement

You are given a non-negative integer `n`.

Find the largest number that is less than or equal to `n` and whose digits are in monotone increasing order.

A number has monotone increasing digits when every digit is less than or equal to the digit after it.

In simple words:

```
Left digit <= Right digit
```

For example:

```
1234  → Valid
1123  → Valid
1359  → Valid
```

But:

```
1324  → Invalid
321   → Invalid
```

Your task is to return the largest valid number that is less than or equal to `n`.

## 2. Examples

Example 1

```
Input:  n = 10
Output: 9
```

Explanation:

```
10 → Invalid (1 > 0)
9  → Valid
```

The largest valid number less than or equal to `10` is `9`.

Example 2

```
Input:  n = 1234
Output: 1234
```

Explanation:

```
1 <= 2 <= 3 <= 4
```

The digits are already monotone increasing.

Example 3

```
Input:  n = 332
Output: 299
```

Explanation:

`332` is not valid because the digits decrease from `3` to `2`.

We need to reduce the earlier digit and make all following digits as large as possible.

```
332
 ↓
299
```

Check:

```
2 <= 9 <= 9
```

Therefore, the answer is `299`.

## 3. Important Points

1. The result must be less than or equal to the given number.
2. Digits must be in non-decreasing order.
3. Equal adjacent digits are allowed.
4. We need the largest possible valid number.
5. When a digit violates the increasing order, we may need to decrease an earlier digit.
6. After decreasing a digit, all digits to its right should become `9` to maximize the result.

Important difference:

| Term                | Meaning                                  |
| ------------------- | ---------------------------------------- |
| Strictly increasing | Every next digit must be greater         |
| Monotone increasing | Every next digit can be greater or equal |

For this problem:

```
112233 → Valid
123456 → Valid
122345 → Valid
```

## 4. Main Concept – Greedy Algorithm

The main greedy idea is:

Find the first position where the digits decrease, reduce the previous digit by one, and make all digits after that position equal to `9`.

But there is one important complication.

Sometimes decreasing one digit creates another violation to its left.

Example:

```
n = 332
```

Digits:

```
3 3 2
```

Compare from left to right:

```
3 <= 3  → Valid
3 <= 2  → Invalid
```

We decrease the second `3`:

```
3 2 9
```

But this is still invalid:

```
3 > 2
```

So we must also decrease the first `3`:

```
2 9 9
```

Now:

```
2 <= 9 <= 9
```

Valid!

This is why we first identify the positions that need adjustment, then fill the suffix with `9`.

## 5. Main Logic – Step by Step

We use three things:

| Variable | Purpose                                                |
| -------- | ------------------------------------------------------ |
| `digits` | Stores the number as a character array                 |
| `mark`   | Stores where we should start replacing digits with `9` |
| `i`      | Traverses the digits from right to left                |

### Algorithm

1. Convert `n` into a character array.
2. Initialize `mark` to the length of the array.
3. Traverse from right to left, starting at the last digit.
4. Compare the current digit with the digit immediately before it.
5. If the previous digit is greater than the current digit:
   - Decrease the previous digit by `1`.
   - Store the current index in `mark`.
6. Continue scanning left because decreasing a digit may create another violation.
7. After the traversal, replace every digit from `mark` to the end with `9`.
8. Convert the character array back into an integer.

### Why do we traverse from right to left?

Consider:

```
n = 332
```

If we only fix the rightmost violation:

```
332 → 329
```

The result is still invalid because:

```
3 > 2
```

We must continue checking towards the left:

```
332 → 229 → 299
```

Therefore, right-to-left traversal helps us handle cascading violations.

## 6. Java Solution – Greedy Approach

```
class Solution {
    public int monotoneIncreasingDigits(int n) {

        char[] digits = String.valueOf(n).toCharArray();

        int mark = digits.length;

        for (int i = digits.length - 1; i > 0; i--) {

            if (digits[i - 1] > digits[i]) {

                digits[i - 1]--;

                mark = i;
            }
        }

        for (int i = mark; i < digits.length; i++) {
            digits[i] = '9';
        }

        return Integer.parseInt(new String(digits));
    }
}
```

## 7. Understand the Code – Line by Line

Part A – Convert the number into a character array

```
char[] digits = String.valueOf(n).toCharArray();
```

Example:

```
n = 332

digits = ['3', '3', '2']
```

This makes it easy to modify individual digits.

Part B – Initialize mark

```
int mark = digits.length;
```

`mark` tells us where to start filling `9`.

Initially, we set it to the array length because no position needs to be changed yet.

Example:

```
digits = [3, 3, 2]
length = 3

mark = 3
```

Part C – Traverse from right to left

```
for (int i = digits.length - 1; i > 0; i--)
```

We start at the last index and move towards index `1`.

Why `i > 0`?

Because we compare `digits[i - 1]` with `digits[i]`. We need a previous digit.

Part D – Check whether digits violate the rule

```
if (digits[i - 1] > digits[i])
```

A violation occurs when the previous digit is greater than the current digit.

Example:

```
3 3 2
    ↑
3 > 2
```

Part E – Decrease the previous digit

```
digits[i - 1]--;
```

If the previous digit is too large, reduce it by one.

Example:

```
3 3 2
  ↓
3 2 2
```

Part F – Update mark

```
mark = i;
```

Remember the position where the suffix should eventually become `9`.

If another violation occurs further left, `mark` will move further left too.

Part G – Replace the suffix with 9

```
for (int i = mark; i < digits.length; i++) {
    digits[i] = '9';
}
```

Why `9`?

We need the largest valid number possible. Once the earlier digits are fixed, filling the remaining positions with `9` gives the largest possible suffix.

Part H – Return the result

```
return Integer.parseInt(new String(digits));
```

Convert the modified character array back into an integer.
