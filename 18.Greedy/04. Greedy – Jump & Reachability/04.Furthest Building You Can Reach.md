# LeetCode 1642 – Furthest Building You Can Reach

## 1. Problem Statement

You are given:

- An integer array `heights`, where `heights[i]` represents the height of the `i-th` building.
- An integer `bricks`, representing the number of bricks available.
- An integer `ladders`, representing the number of ladders available.

You start at building index `0` and want to move towards the right.

To move from building `i` to building `i + 1`:

1. If the next building is shorter or equal in height, you can move without using anything.
2. If the next building is taller, you must use either:
   - Bricks equal to the height difference.
   - One ladder, regardless of the height difference.

Your task is to return the furthest building index you can reach.

## 2. Examples

Example 1

```
Input:
heights = [4,2,7,6,9,14,12]
bricks = 5
ladders = 1

Output: 4
```

Explanation:

| Movement | Height difference | Resource used |
| -------- | ----------------- | ------------- |
| 4 → 2    | Down 2            | Nothing       |
| 2 → 7    | Up 5              | Ladder        |
| 7 → 6    | Down 1            | Nothing       |
| 6 → 9    | Up 3              | Bricks        |
| 9 → 14   | Up 5              | Cannot afford |

We reach building index `4`, whose height is `9`.

We cannot reach building index `5`, whose height is `14`.

Therefore:

```
Output = 4
```

Example 2

```
Input:
heights = [4,12,2,7,3,18,20,3,19]
bricks = 10
ladders = 2

Output: 7
```

We can reach building index `7`, but cannot afford the climb to index `8`.

## 3. Important Points

| Situation                | What happens?           |
| ------------------------ | ----------------------- |
| Next building is shorter | No resource needed      |
| Next building is equal   | No resource needed      |
| Next building is taller  | Need bricks or a ladder |
| Large height difference  | Prefer using a ladder   |
| Small height difference  | Prefer using bricks     |

Main observation:

We should save ladders for the largest height differences and use bricks for the smaller height differences.

But how do we know which climbs are the largest?

We use a Min Heap (Priority Queue).

## 4. Main Concepts – Greedy + Priority Queue

### Why Greedy?

Suppose we have these upward climbs:

```
[2, 5, 3, 7]
```

And we have:

```
Bricks = 5
Ladders = 1
```

We should use the ladder for the largest climb, `7`.

We can use bricks for the remaining climbs:

```
2 + 5 + 3 = 10
```

However, we only have 5 bricks, so we cannot afford all three.

The best strategy is to reserve the ladder for the largest climb and spend bricks on the smaller climbs.

### Why Min Heap?

A Min Heap always gives us the smallest element first.

We store all upward climbs in a Min Heap.

Whenever the number of stored climbs becomes greater than the number of ladders:

1. Remove the smallest climb from the heap.
2. Pay for that climb using bricks.
3. If bricks become negative, we cannot reach the current building.

Why remove the smallest climb?

Because ladders should be reserved for the largest climbs.


The smallest climb is removed first and paid for with bricks. Ladders remain available for the larger climbs.

## 5. Main Logic – Step by Step

We use:

```
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
```

This stores the upward height differences.

Algorithm:

1. Create a Min Heap.
2. Traverse buildings from index `0` to `n - 2`.
3. Calculate the height difference:
   ```
   int climb = heights[i + 1] - heights[i];
   ```
4. If `climb <= 0`, move forward without using resources.
5. If `climb > 0`, insert it into the Min Heap.
6. If heap size becomes greater than `ladders`:
   - Remove the smallest climb.
   - Subtract it from bricks.
7. If bricks become negative, return the current index `i`.
8. If all movements succeed, return the last index.

## 6. Java Solution – Optimal Greedy

```
import java.util.PriorityQueue;

class Solution {
    public int furthestBuilding(int[] heights, int bricks, int ladders) {

        PriorityQueue<Integer> minHeap = new PriorityQueue<>();

        for (int i = 0; i < heights.length - 1; i++) {

            int climb = heights[i + 1] - heights[i];

            if (climb > 0) {
                minHeap.offer(climb);
            }

            if (minHeap.size() > ladders) {
                bricks -= minHeap.poll();
            }

            if (bricks < 0) {
                return i;
            }
        }

        return heights.length - 1;
    }
}
```

## 7. Understand the Code – Line by Line

Part A – Create Min Heap

```
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
```

- Stores upward height differences.
- The smallest climb stays at the top.
- `poll()` removes the smallest climb.

Example:

```
Insert: 5, 3, 7

Min Heap:
       3
      / \
     5   7
```

Part B – Traverse the buildings

```
for (int i = 0; i < heights.length - 1; i++)
```

We compare the current building with the next building.

For an array of length 7:

```
i = 0, 1, 2, 3, 4, 5
```

We stop at the second-last index because each iteration checks the next building.

Part C – Calculate the climb

```
int climb = heights[i + 1] - heights[i];
```

Example:

```
heights[i]     = 2
heights[i + 1] = 7

climb = 7 - 2
      = 5
```

A positive value means we need resources.

Part D – Store positive climbs

```
if (climb > 0) {
    minHeap.offer(climb);
}
```

If the next building is taller, insert the height difference into the heap.

If the next building is shorter or equal, do nothing.

Part E – Check whether we have exceeded our ladder count

```
if (minHeap.size() > ladders) {
    bricks -= minHeap.poll();
}
```

This is the most important greedy operation.

If the number of upward climbs is greater than the available ladders, we must use bricks for one climb.

We choose the smallest climb because the ladders should be saved for larger climbs.

Part F – Check available bricks

```
if (bricks < 0) {
    return i;
}
```

If bricks become negative, we cannot reach the next building.

Therefore, return the current building index.

Part G – Return the last index

```
return heights.length - 1;
```

If we successfully complete every movement, we can reach the last building.
